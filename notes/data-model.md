# G Series PPS V00-04-00-48: codeplug data model

Reverse-engineering notes for a cross-platform replacement of Unication's
"G Series PPS" (G4/G5 voice pager programming software). Paths in `file:line`
references are relative to `../decomp/` (ILSpy output)
unless stated otherwise. Installed data lives under
`extract/msi/Unication/G_Series_PPS_V00-04-00-48/` (called `$INST` below).

Full DDL dumps (with the vendor's inline comments preserved) are in
`notes/schema/*.sql`. Converted SQLite 3 copies of every shipped DB are in
`scratch/db3/`.

## 0. Summary

- Everything is SQLite **2.1** (`** This file contains an SQLite 2.1 database **`),
  accessed through a native `SQLiteDll.dll` exporting the SQLite 2 C API
  (`sqlite_open`, `sqlite_get_table`, `sqlite_exec`, `sqlite_free_table`,
  `sqlite_close`): `DataBase/Unication.SQLite/SQLiteAPI32.cs:8-21`. Text is
  passed as UTF-8 (`SQLiteAPI.cs:50-58`, `UTF8Marshaler.cs`).
- There are **two different databases** in play:
  1. The **PC profile DB** ("PPS format", template `$INST/DataBase/PPS_G4A.db`,
     163 tables, internal version `tabDBVersion` = 8.0). This is what the user
     edits. Each profile is `<GUID>.db` plus a sibling folder `<GUID>/` holding
     one SQLite file per P25 trunking system, per-profile alert tone and voice
     prompt catalogs, custom `.wav` files and an optional home-screen logo.
  2. The **radio DB** `u3db.db` ("U3DB format", templates
     `$INST/DataBase/DB_Base/DB_Base_G4A.DBV<ver>.db`, 60 tables for DBV2.0x).
     PPS *generates* it from the profile at program time with a per-version
     converter (`PPSU4ParamConverter_<ver>`). The pager runs this DB, not the
     PC profile.
- On programming, PPS uploads `u3db.db` + `.md5`, the raw profile as
  `u3db_PC.db`, and a zip of profile + resource folder as `u3db_PC.zip` +
  `.md5`, all under `/defpara/Applications/PPS/`, plus G.729 `.dat` tones and the
  logo (`View/View.ProgramVersion/ProgramController.cs:441-526`).
- On read, PPS only uses `u3db_PC.zip` (or legacy `u3db_PC.db`) to recover the
  profile. It also fetches the radio's `u3db.db` but the merge step
  `RestoreU3DBDataToPPS` is an empty stub that returns `true`
  (`View/View.Profile/ProfileManagerBiz.cs:544-547`). So the radio DB is
  write-only from PPS's perspective; edits made on the pager are lost on read.
- P25 trunking systems are not in the profile DB proper. The profile has an
  index table (`tabP25TrunkingSecurity`) and each system is its own SQLite file
  built from `$INST/DataBase/P25TSystem.db`. `P25TTotal.db` is the index of a
  user-level "public resource" library of systems. **Both ship empty**: there is
  no bundled database of public P25 systems. Systems are hand-entered, imported
  from RadioReference CSV exports or the RadioReference premium SOAP API, or
  imported from another PPS export zip.
- A "channel" is a (zone, knob position) pair: up to 64 zones x 8 knob
  positions, each with a receive mode and one detail row (conventional,
  scan, free scan, or P25 trunking). In the radio DB this becomes
  `ZoneKnobID = zone * 100 + knob`.
- All frequencies are stored as integer **Hz**. The radio DB has no Tx
  frequencies (receive-only pager) and no P25 band plan table.
- Two version axes: profile schema (`tabDBVersion`, now 8.0, migrated by
  `View/View.UpdateVersion/*`) and radio schema (`DBV1.41a`..`DBV2.06`, chosen by
  what the pager reports, generated by `PPSU4ParamConverter_*`).
- All 140 G5 models are dual band, 700/800 plus VHF, UHF B/C/D or low band;
  all but G5B36BF support P25 trunking.
- No encryption key material is stored anywhere; only key IDs/aliases/CKRs.

## 1. Files, formats, tooling

### 1.1 SQLite 2 tooling

- Built SQLite 2.8.17 from `https://www.sqlite.org/sqlite-2.8.17.tar.gz` in
  `scratch/sqlite2/`. The bundled `config.sub` fails on Apple Silicon; configure
  with `--build=x86_64-apple-darwin --host=x86_64-apple-darwin --disable-tcl
  --enable-utf8` and `CFLAGS="-O2 -std=gnu89 -Wno-implicit-function-declaration
  -Wno-int-conversion -Wno-implicit-int"`. A static shell is at
  `scratch/sqlite2/sqlite2` (links `.libs/libsqlite.a`, no dylib dependency).
- `scratch/dump_sqlite2.sh in.db [out.sql | out.sqlite3]` (`--schema` for DDL
  only). SQLite 3 output prepends `PRAGMA ignore_check_constraints=ON`, because
  SQLite 2 parses CHECK constraints but never enforces them and the shipped radio
  templates violate their own CHECKs (`tabMemory.AlertLv1 > 0` fails on several
  rows). Row counts were verified identical across all 163 profile tables after
  conversion.
- Reverse direction (needed to produce files the pager and PPS accept):
  `sqlite3 x.sqlite3 .dump | sed '/^PRAGMA/d' | sqlite2 out.db`. Not yet
  exercised against hardware.
- SQLite 2 is typeless: every value is stored as text. Code reads values with
  `Convert.ToInt32(row[...].ToString())` everywhere, so integer columns
  containing `''` show up in templates (e.g. `tabConvFreqList.RxFreq` is empty in
  `PPS_G4A.db`). A reader must tolerate empty strings in "INTEGER" columns.

### 1.2 Legacy at-rest encryption of user-data DBs

`DataBase/Unication.SQLite/SQLiteAES.cs:13-110`: on startup
(`G_Series_PPS/New_PPS/Program.cs:37`) and exit (`Program.cs:67`) PPS walks the
user-data root and, for every `*.db` that does not contain the SQLite 2 banner,
AES-decrypts it in place (RijndaelManaged defaults = AES-128-CBC, PKCS7; key =
UTF-16LE `"P@ssw0rd"`, IV = UTF-16LE `"Dr0wss@p"`, both 16 bytes). Both
`dbEncrypt` and `dbDecrypt` call `decrypt()`, so this build never encrypts
anything; it only undoes encryption left by older PPS builds. A new app that
imports an existing `C:\ProgramData\Unication\...\UserData` tree should apply
the same "no banner, try AES decrypt" rule.

### 1.5 Profile export file `.unipps`

### 2.2 Program (write) flow

`ProgramController.Program` (`:61-169`) -> `ProgramData` (`:205-260`):

1. Pre-checks: profile passes `ProfileCheckHandler.CheckProfileData`
   (`View/View.ProfileCheck/ProfileCheckHandler.cs:245-301`, rules in 2.5),
   pager model valid and enabled, pager U3DB version supported, product and
   band codes match (section 4.1), access password if set.
2. Copy profile `<GUID>.db` and its folder to `Temp\Convert\`.
3. `ChangeDB` (`:262-393`): if the pager's model differs, write the new model,
   re-copy MFG/BSS, remap frequencies to the pager band, delete protocols the
   pager lacks.
4. `ConvertToU3DB` (`:395-439`): copy template
   `DB_Base\DB_Base_G4A.<ver>.db` to `U3DB_Public.db`, run
   `convertPublic`, copy to `U3DB_Member.db`, run `convertPrivate`. The
   template is edited in place via the SQLite 2.8.3 engine, so **u3db.db stays
   SQLite 2.1** (bundled `SQLiteDll.dll` reports version `2.8.3`, UTF-8 build;
   statements run in `begin; ... commit;` batches of 5000,
   `DataBase/Unication.SQLite/SQLiteDataBase.cs:178-222`; no PRAGMA or VACUUM).
5. `ProgramFile` uploads the files in 2.1 via `U3Device.ProgrammingFiles`.

### 2.3 Read flow

`View/View.ReadDevice/ReadProfileFromDeviceControl.cs`:

1. `ReadProfileFromDevice` (`:154-260`): list `/defpara/Applications/PPS/`; if
   `u3db_PC.zip` is there, fetch and unzip it; else try
   `/root/Applications/u3db/u3db_PC.zip`; else fetch the bare
   `/root/Applications/u3db/u3db_PC.db`. If the pager's U3DB version is
   supported, also fetch `/root/Applications/u3db/u3db.db` (`RestoreU3DBToTemp`,
   `:262-286`; note the old path, not `/defpara`).
2. `goToNewProfile` (`:288-356`): upgrade the recovered profile with
   `DBUpdateChecker.Check` (section 6.1); rewrite the model if the pager's model
   differs (`CheckIfModifyModelNo` / `UpdateModelNo`); call
   `RestoreU3DBDataToPPS(u3db, pcdb, ver)`, which **does nothing** and returns
   `true` (`View/View.Profile/ProfileManagerBiz.cs:544-547`); then save as a
   new or overwritten profile keyed by the profile GUID.

So: **the pager runs a generated radio-format DB; the PC DB rides along only so
it can be read back.** A pager programmed by a third-party tool that only
writes `u3db.db` would read back with the stale `u3db_PC.zip` (or nothing).
Our tool must write both, and may need its own `u3db.db` -> profile importer
for pagers whose `u3db_PC.zip` is missing or stale. (The 2.0x converter has an
`updateDataToPPS` path at `PPSU4ParamConverter_02P01.cs:~4114` that maps zones
back by `ZoneNo`, but nothing calls it from the read flow.)

### 2.4 The PPS -> u3db converter (DBV2.06)

Chain: `PPSU4ParamConverterBase` -> `_02P01` (nearly all logic) -> `_02P02`
-> `_02P03` -> `_02P04` (empty) -> `_02P05` -> `_02P06`
(`View/View.ProgramVersion/`). `CheckProfile()` in the converter always returns
`true` (`PPSU4ParamConverter_02P01.cs:38-41`).

`convertPublic` (`02P01.cs:322-384`), in order: `convertZone`;
contacts (conventional groups, P25C sub-groups, members, then per P25T knob the
system's TGs and sub-groups); single conventional knobs (`convertSingleCHKnobInfo`,
signaling, receive group list); advanced conventional knobs; P25 trunking knobs
(`convertP25TSignaling`, knob info, receive group list, call alert, P25T
members); scan lists; all-band scan; `convertFunction` (device settings into
`tabFuncParam` etc.); detail-screen items; dispatch manual ACK texts; custom
tones / announcements; encryption keys.
`convertPrivate` (`02P01.cs:126-233`): menus (`tabMenuListLayout`), function
status/settings lists, passive workstation functions, debug entries; deletes
template zones 1025 (free scan) / 1100 (channel setting) when functions 141 /
161 are off; BLE settings.

**ID renumbering** (GUID -> integer):

| Radio key | Rule | Evidence |
| --- | --- | --- |
| `tabZone.ZoneID` | 1..N in `tabZone_New` row order (`ZoneNo` ignored) | `02P01.cs:101-124` |
| `ZoneKnobID` | `zoneIndex * 100 + KnobIndex` (e.g. zone 1 knob 3 = 103) | `02P01.cs:60-99` |
| conventional `SigID` | = `ZoneKnobID` | `02P02.cs:48` |
| P25T `SigID` | 1..N per distinct (`P25TrunkingID`, `ProtocolSettingID`) in knob order | `02P01.cs:2579-2590` |
| group `ContactID` | 1.. in first-seen order (key GroupID, or `sysGUID_GroupID` for P25T) | `02P01.cs:573,634,749-754` |
| sub-group `ContactID` | from 10000000 (2.06) | `02P01.cs:671,833-866,916` |
| pager's own contact | 9999999 (2.06; 99999 in <= 2.05) | `02P06.cs:10-13` |
| all-call contact | 9999998 (2.06) | `02P06.cs:15-18` |

**Key table mappings** (radio table <- profile source):

- `tabZone(ZoneID, ZoneName)` <- `tabZone_New.Name`; `tabCurrentZoneAndLocked.CurrentZoneID` = 1.
- `tabKnobInfo` (one row per active knob; `02P02.cs:534-566`): `Name` <-
  `tabReceivingMode_NewG4.ChannelName`; `RecvMode` <- `GetRecvMode(CurrentMode)`
  (`PPSU4ParamConverterBase.cs:92-123`: 1->1, 33->32, 4/36/68->4, 8->8, 16->16,
  48->64, 65->1, 97->97, 128/129->128); `PromptID` <- announcement ID;
  `SignalingType` <- `tabProtocolSetting.ProtocolType`; `SigID`;
  binding/reset/TGID-stay/Delay-N/record-delay timers; `PTL`, `Privacy`,
  `VoiceStorage` <- `RecordFlag`; voice buffering; `AlertMode` = PPS value - 1;
  `SquelchOption`; `SecureFunction` <- `EncryptedCallFlag`; `ForceDrop`.
- `tabChannel` (`02P02.cs:56-168,312-410`): `RXFrequency` <- `tabConvFreqList.RxFreq`
  (Hz; **Tx is discarded, the pager is receive-only**); `RxChanBandWidth`
  unchanged (1/2/3); `isSupportRepeater` = `TransmitMode == 0`;
  `CarrierSquelchSetting`/`SINADSquelchSetting` from `AudioSquelch` 0..3 ->
  51/102/153/255 and 4/8/12/20 (`02P01.cs:1788-1801`);
  `SignallingSquelchLogic` 0 selective / 1 monitor; `PowerSavingRxOffDur` by
  protocol (CSQ 100, MDC/DVOA 100, others 0; two-tone by tone set 600/1600/350;
  Engineer login uses `tabPowerSavingSetting`); `NumOfSA` and up to five
  `SATypeN`/`CTCDN`/`CDModeSenseN`/`SAnSig` from `tabRecvSaList` (CTCSS in
  0.1 Hz, DCS as integer of the octal code; `SAnSig` = protocol type, 255 if
  none).
- `tabP25Signaling` (SigID = ZoneKnobID): timers from the protocol setting,
  `RxNAC` from the knob (template default 3966 = 0xF7E), `EncryptedCallFlag`.
  `tabDMRSignaling`, `tabTwoToneSignaling` (2.05+ thresholds),
  `tabFiveToneSignaling`, `tabMDC1200Signaling` similarly.
- `tabContacts(ContactID, SignalingType, Address, Alias, AlertMode,
  AlertToneIndex, VoiceStorage, RelayControl, RelayOnTime, BackgroundColor)`:
  one row per group per used protocol. **Group addresses for DMR (4), P25C (8)
  and P25T (9) get bit 31 set** (`addr + 2147483648`, `02P01.cs:946-953`).
  Sub-group addresses become strings like `0_<sub>_<grp>` or
  `<1|2>_<a>_<b>_<grp>` (`:955-969`). All-call rows (9999998) per protocol
  (no P25T all-call row). The pager's own rows are pre-seeded in the template
  and UPDATEd; its P25T address is `tabPagerSUID.P25TAddr` (default 268435455
  = 0x0FFFFFFF).
- `tabMemberList(ID, SignalingType, Address, Alias, SigID)` <- conventional
  members and P25T individual calls from each system DB.
- **P25 trunking** (`02P01.cs:2573-2693`), once per (system, protocol setting):
  - `tabP25TrunkingSignaling`: `WacnID`, `SystemID`, `SiteTrunkingFlag`,
    `SystemName`, `SUID` (default 268435455) from the system DB's
    `tabP25TrunkingSystem`; `RfssRspWaitTimeout`, `MFID`, `AlgId`, tone timings
    from the profile `tabP25TSignaling`; `PhaseIIRx` = 0 and
    `RssiThreshold` = 10 hard-coded; `FullSpectrumScanRanges` (0 if flag off)
    and `Start/End/StepSizeOfRange1..3` (empty slots filled with the first Rx
    range of the model's first band, MHz truncated to integer before x1e6; step
    default 12500) (`PPSU4ParamConverterBase.cs:2891-2968`).
  - `tabP25TrunkingSites(SigID, ItemType, RfssID, SiteID, RxChFreq, SiteName, SeqNo)`:
    every distinct control-channel frequency -> `ItemType 1` row (`RfssID` 0,
    `SiteID` 0, `RxChFreq` Hz); every distinct RFSS/site -> `ItemType 0` row
    (`RxChFreq` 0). `SeqNo` counts down from 256. The site-to-CC link table,
    CC bandwidth/Tx, `ErrorRateThreshold` and `ConverageType` are dropped;
    `ItemType 2` is never written.
  - **No band plan / IDEN table exists** in the radio DB. Presumably the
    pager learns channel identifiers over the air from the control channel
    (standard P25 IDEN_UP behavior), so the codeplug only carries
    control-channel frequencies or full-spectrum hunt ranges.
  - `tabP25TSetting(ChannelID=ZoneKnobID, ATGID, EncryptedCallFlag,
    MSELCallSamplingFlag, MaxMSELSamplingTime)`.
  - `tabCallAlertGroup` from the call-alert tables.
- `tabRecvGroupList(ZoneKnobID, SigType, SigID, ContactID, SeqNo)`: the knob's
  receive talkgroups (P25T `SeqNo` = priority order from `tabChannelGroup`);
  `tabRevertListGroup.RevertAddress` actually stores a ContactID;
  `tabRecvBehaviorByContactID` per-contact status (1 priority / 2 etc.) and ack flags.
- `tabScanListSettings` (`02P01.cs:2465-2478`): `ScanListSettingID` =
  ZoneKnobID; `ScanList` = comma-separated member ZoneKnobIDs (excluding
  priority channels); `PriorityZoneKnobID` = `"a,b"` string in an INTEGER
  column; `StayTime`, `RecvAllFlag` <- `OpenSpeaker`, `PriorityIntervalTime`
  <- `DwellTime`, `CtCdRequest` <- `MatchCTCD`.
- `tabAllBandScanParam` <- `tabAllBandScanBandParam` (+ knob bandwidth/stay time).
- Tones: `AlertToneIndex` 9999 -> 1, 10000 -> 2, 1..8 -> 3..10, custom
  GUID -> 100 + n; announcements 1..20 -> 50..69, custom -> 164 + n; each custom
  file gets a `tabAlertToneFile` row pointing at
  `/defpara/Applications/chvoicerecord/G4-Tone-NNN.dat` or `G4-ChVoice-NNN.dat`
  (`02P01.cs:478-562`, `PPSU4ParamConverterBase.cs:238-268`). More than 64
  custom tones would collide with prompt IDs (both lists allow 100).
- Encryption (`02P01.cs:3481-3827`): `tabEncryptionSetting`, `tabKVLUSBConnect`,
  `tabKMFSystem`, `tabP25OTARFeatureControl`; when `EncryptionType == 3` also
  `tabEncryptionKeyList(seq, KeyID, KeyAlias, CKR)` and
  `tabCipherKeyAssignment(CHID, KeyName, CKR, KeyID, Type, AssignmentID, 2, 0)`
  with Type 1 channel key (AssignmentID (zone-1)*16 + (knob-1)), 2 per-group key
  (AssignmentID = raw TG), 4 private, 6 dynamic regroup. **No key material.**
- `tabFuncParam`: the single wide row of device settings, UPDATEd from the
  general-settings tables (section 3.7); `UserCompany` <- `tabOrganization_New`;
  `Pwd1Content`/`Pwd2Content` <- access-password MD5s; `CradleType` 1 for TT

### 2.5 Pre-programming validation (the real hard limits)

`ProfileCheckHandler.CheckProfileData` (`View/View.ProfileCheck/ProfileCheckHandler.cs:245-301`),
checking knobs 1..8 per zone:

| Code | Rule | Lines |
| --- | --- | --- |
| A1 | at least one knob in some zone has `CurrentMode != 0` | 296-299 |
| B2 | the knob's detail row exists for its mode; its `ProtocolSettingID` resolves | 541-553, 583-621, 703-712 |
| B1 | `ConvFreqID` exists in `tabConvFreqList` | 559-563, 622-627 |
| D1 / D2 | DMR or P25C need `RxBandWidth == 1`; others need `RxBandWidth != 0` | 317-327 |
| B3 | each protocol's receive grouping has >= 1 group with an address, no duplicate addresses; sub-group feature on needs >= 1 sub-group | 359-460 |
| C1 | a P25T knob's system is in `tabP25TrunkingSecurity` and `<profile>\<GUID>.db` exists | 714-730 |
| B3 (trunking) | >= 1 TG with a `P25TAddr`; no duplicate TGIDs; non-empty revert list has a valid TG; sub-groups present if enabled | 462-536, 757-796 |

## 3. Profile DB schema by concept (PPS_G4A.db, version 8.0)

163 tables. Full DDL with the vendor's comments: `notes/schema/PPS_G4A.sql`;
one-line-per-table listing with template row counts in Appendix A. Below, tables
are grouped by concept with meaning and the limits the UI enforces. "UI:" means
enforced in a WinForms control; "(resx)" means a designer limit in the
`.resx` file next to the control; "not enforced" means I found no check.

### 3.0 Conventions

- **Keys are GUID strings** (`VARCHAR(64)`) for zones, channels, groups,
  members, protocol settings, frequencies, trunking systems. The literal
  `'0000000000000000'` (16 zeros) means "CSQ / none" for protocol-setting IDs;
  `'000000000000'` (12 zeros) means "no key" for encryption-key IDs. The
  converter renumbers GUIDs to integers for the radio DB (section 2.3).
- **A "channel" in the UI is a (Zone, KnobIndex) pair.** The pager has a
  rotary knob; each zone has knob positions, and each position has a receiving
  mode stored in `tabReceivingMode_NewG4`. The detail row lives in one of
  `tabSingleConvCHKnob` (single conventional channel), `tabAdvancedConvCHKnob`
  (radio-compatible conventional), `tabMultiChannelScan` (+ `tabMultiCHScanList`)
  (scan list), `tabAllBandScanCHKnob` (+ `tabAllBandScanBandParam`,
  `tabAllBandScanProtocolParam`) (free/band scan), or
  `tabP25TrunkingSystemKnob` (P25 trunking). Each detail row has a GUID
  `ChannelID` that the group-selection tables reference.
- **Knobs per zone: 8 in the UI** (`View/View.Zone/ZoneListControl.cs:78`,
  `ZoneKnobInfoControl.cs:157`, RadioReference import `RadioReferencehandler.cs:784`),
  although the template ships 16 `tabReceivingMode_NewG4` rows for its one zone.
  Zones: max 64 (`ZoneListControl.cs:82`). Zone/knob alias: 14 chars in the UI
  (`ZoneListControl.cs:4079`, `ZoneKnobInfoControl.cs:531,541`) though
  `tabZone_New.Name` is `VARCHAR(30)`.
- **Frequencies: integer Hz.** UI shows MHz with 5 decimals and saves
  `Convert.ToInt32(MHz * 1000000)` (`View/View.P25TSystem/ControlCHControl.cs:488`,
  `View/View.FrequencySetting/FreqSettingControl.cs:468`). The 12.5 kHz spinner
  step is cosmetic; paste/import accept any in-range value.
- **Band limits** come from `Data_G4A.tabRFBandRanges` for the profile model's
  first and second band, `RxTx=0` rows for Rx (`FreqSettingControl.cs:339-380`,
  `View/View.Profile/BaseDataRepository.cs:82-126`, `View/View.Common/Common.cs:270-382`).
- **Shared enums** (`View/View.Common/NameValueVModel.cs`):
  - `AlertMode` (`:21`): 1 tone, 2 vibrate, 3 none/silent, 4 tone + vibrate (0 = "default", inherit, in group/member rows).
  - `BackgroundColor` (`:65`): 0 off/black, 1 green, 2 blue, 3 cyan, 4 red, 5 yellow, 6 magenta, 7 white.
  - `KeyStrapOption` (`:111`): 0 clear, 1 secure, 2 user select.
  - `AlertToneID` (`:175`): 0 none, 9999 default, 10000 chirp, 1..8 built-in "Tone n", else a custom tone GUID from `AlertToneTotal.db`.
  - `Relay` (`View/View.GroupSetting/GroupList.cs:428-466`): 0 off, 65535 always on, 1..600 s timeout.
  - `DutyStatus` on knobs: 1 duty on, 2 duty off; on groups 0 default, 1 on, 2 off.
  - `RecordFlag`: 0 no, 1 record (single conv knob: 0 none, 1 ID match, 2 all voice).
- **`ProtocolType`** (`View/View.Profile/ProtocolType.cs:3-21`): -1 None, 0 CSQ,
  1 TwoTone, 2 FiveSixTone, 3 ARDS, 4 DMR, 5 MDC1200, 6 DTMF, 7 DVOA, 8 P25C,
  9 P25T; sub-group pseudo-types 801/802/803 (P25C two-tone type 1, unit
  address, two-tone type 2) and 901/902/903 (same for P25T).
- **Receiving mode** `tabReceivingMode_NewG4.CurrentMode`
  (`View/View.Profile/ReceivingModeType.cs:3`): 0 none, 1 selective call
  (single conventional), 4 normal scan, 8 free scan, 16 trunking TG scan,
  33 monitor mode, 36 priority scan, 48 trunking TG monitor, 65 multi selective
  call (Engineer only), 68 silent scan, 97 multi monitor (Engineer only),
  128 radio-compatible mode, 129 radio-compatible trunking. 16/48 only on
  models with P25T. UI list `NameValueVModel.cs:283-358`.

### 3.9 Encryption

- **No key material is stored anywhere in the profile or radio DB.** Only key
  IDs, aliases and CKRs; actual keys must be loaded with a KVL over the
  USB-RNDIS link (`tabKVLUSBConnectionSetting`: 192.168.128.1/.2 port 49165).
- `tabEncryptionSetting`: `EncryptionType` has no UI (template 3 = KVL; the
  converter writes 3 if 3, else 1, and emits keys only for 3); editable
  `PeriodicKeyfailAlert` 0/1, `DisplayOnChannelChange` 0 off / 1 keyset name
  (`View/View.SecureSetting/SecureGeneralSettingControl.cs`).
- `tabEncryptionKeyList`: `ID` GUID, `KeyID` (auto, schema says 1-4095, not
  range-checked), `KeyAlias` ("Key n"), `CKR` 0-4095 unique; >= 1 row, max 1024
  (`EncryptionKeyControl.cs:32,70`). EKF import (`*.ekf`, `:196-276`) copies only
  KeyID/alias/CKR; it writes the decrypted EKF payload to
  `<UserData>\Temp\<guid>.txt` (`EKFFileConverter.cs:~362-372`), which can leave
  plaintext on disk.
- Per-channel key selection columns on knobs (`EncryptionBy`,

## 4. Models: MFG_G4A.db, BSS_G4A.db, model-number decoding

### 4.1 What the two per-model DBs hold

- **`MFG_G4A.db`** (hardware identity; DDL `notes/schema/MFG_G4A.sql`):
  `tabMfgProductCode` (series code/number, hardware block string
  `BXXXXX`/`BLXXXX`, single/dual band, first and second `RFBandTypeID`,

  to the folder name), plus empty serial placeholders `tabMfgProductMsn`,
  `tabBoardVersionBSN`.
- **`BSS_G4A.db`** (business/feature layer; `notes/schema/BSS_G4A.sql`):
  `tabProtocolMode` (one row of protocol flags), `tabFunctionList`
  (FunctionID/Enable), `tabPowerLevel`, `tabBusinessOption`, `tabCustomer`,
  `tabCustomerSupport`, `tabProductAppearance`, `tabTowTruckSetting`,
  `tabVoiceCallVocoderSetting`.

Neither goes to the pager as a file. They're **copied into the profile** when a
profile is created and again (into the temp copy) whenever the profile is
programmed into a pager of a different model:
`ProfileManagerBiz.PrepareNewDB` (`View/View.Profile/ProfileManagerBiz.cs:128-202`)
-> `U4PPSDataRepository.CopyMfgDBAndBbsDB` (`View/View.Profile/U4PPSDataRepository.cs:515-575`)
writes `tabMfgProductCode`, `tabCustomer`, `tabProtocolMode`,
`tabVoiceCallVocoderSetting`, `tabProductAppearance`, `tabPowerLevel`,
`tabTowTruckSetting`, `tabFunctionList` and seeds/intersects
`tabMemberFunctionList`. Then `SaveModel` writes `tabModel`, and a default
frequency is set to the band's RxMin / RxMin+12.5 kHz (`ProfileManagerBiz.cs:183-195`).

Quirk: `tabBusinessOption` from BSS is never read. `CopyMfgDBAndBbsDB:532`
calls `BaseDataRepository.GetBusinessOption()`, which reads `Data_G4A.db`.
Effective global limits (`Data_G4A.tabBusinessOption`): 256 channels, 64 zones,
1024 conventional frequencies, 1024 trunking systems, 256 control channels per
system, 256 sites per system, 16 protocol settings, 8192 groups, 999 radios.

At conversion the MFG/BSS data acts as a filter: menu rows from
`Data_G4A.tabMenuBase` whose `Model` contains e.g. `"G5"`, and functions whose
`HWBlock` letter is in the hardware code and that are enabled in the member
function list (`View/View.ProgramVersion/PPSU4ParamConverterBase.cs:2319-2610`).

Model selection at program time: the pager reports its model number in the
handshake; PPS truncates to 21 chars (`ProgramController.cs:79-80`), validates
it (`:82-87`), requires an enabled `tabModelNumberInfo` match via
`ModelNumberCode.isContain` (`:89`, `View/View.Profile/ModelNumberCode.cs:183-194`,
compares product, hardware, protocol, software, both bands, language; ignores
the last 7 chars), refuses mismatched product code, band pair, or tow-truck
software (`:105-135`), warns and strips protocols on hardware/protocol mismatch
(`:138-151`, `getRemoveProtoclList` `:183-203`, deletion SQL in `ChangeDB`
`:262-393`), then `ChangeDB` re-copies the pager's model folder
(`FindModelInfoInAllModel(ModelNumber.Substring(0,14))`, first folder containing
those 14 chars wins) and re-maps frequencies to the new band (`updateFreq`
`:600-662`).

### 5.2 How systems get into a profile

1. **Create in PPS**: `button_add_Click` (`P25TSyetemTotal.cs:742-788`) makes a
   GUID, copies `P25TSystem.db`, inserts the system row, `Site 1`
   (RFSS 1, Site 1), one control channel at the band's RxMin, and the band row
   (`newP25Trunking`, `:970-1025`), then opens the editor.
2. **RadioReference site CSV**: `button_importCsv_Click` (`:1390-1465`).
   Requires columns `RFSS`, `Site Dec`, `Description`, `Frequencies` (`:1418`);
   `ImportCsvDataToSystem` (`:1489-1561`) creates one site per distinct
   (RFSS, Site Dec) (name = Description truncated to 14, `Site Hex` used if
   decimal > 255), and one control channel per distinct frequency in the
   comma-separated `Frequencies` list (`RxFreq = MHz * 1e6`, bandwidth 0, Tx 0).
   Max 256 sites and 256 frequencies per system (`:1431-1432`). It does not
   populate `tabP25TrunkingSiteControlCH`. A separate talkgroup CSV importer
   is `ImportCsvForTGIDControl.cs` (section 3).
3. **RadioReference SOAP API** (premium account required):
   `RadioReferencehandler.dealWithTrunking(...)` called from
   `G_Series_PPS/New_PPS/MainForm.cs:90-91` (into the library) and
   `View/View.EditProfileUI/EditProfileControl.cs:1137-1139` (into the open
   profile).
   - Endpoint `http://api.radioreference.com/soap2/index.php`
     (`G_Series_PPS/app.config:53`), `authInfo` with Unication's own appKey (redacted), version
     `latest`, user/password from the login form
     (`RadioReference/RadioReference/RadioReferenceController.cs:99-104`);
     credentials optionally saved AES-encrypted with a hard-coded key in
     `login`/`login2` files next to the exe (`:120-171`). Login checks
     `getUserData.subExpireDate` is "Never" or in the future
     (`RadioReferenceLoginForm.cs:113-124`). Calls: `getTrsDetails`,
     `getTrsSites`, `getTrsTalkgroups`, `getTrsTalkgroupCats`, plus geography
     lookups. Only `sType == 8` (P25) systems are listed (`RadioReferenceForm.cs:692,725`).
   - Mapping (`View/View.RadioReference/RadioReferencehandler.cs:151-565`):
     `Name` = `trs.sName`[0:14]; `WacnID` = hex parse of `sysid[0].wacn`
     (default 0xFFFFF = any); `SystemID` = hex parse of `sysid[0].sysid`
     (default 0xFFF); `SystemSource` = `RadioReference-<sid>`;
     `FullSpectrumScanFlag` 0; `SiteTrunkingFlag` 0; `ErrorRateThreshold` 5.
     Sites (max 256): `siteDescr`[0:14], `rfss`, `siteNumber`. Control channels
     (max 256): primaries (`use == "d"`) first, then alternates (`"a"`), then
     the rest; `RxFreq = TxFreq = MHz * 1e6`, bandwidth 1, linked in
     `tabP25TrunkingSiteControlCH` (`:480-543`). Talkgroups: `tgAlpha`[0:14],
     `P25TAddr = tgDec`, `Note = tgDescr`, `AlertMode` 3, `KeyStrapOption` 1;

     the narrowest band containing every frequency (`:55-119`); for a
     profile, every frequency must fit the profile band or the import aborts
     (`:34-53`). Optionally creates a zone with knob 1 in mode 16 and a P25T
     protocol setting (`:237-419`).
   - Conventional "agency" import (`dealWithAgency`, `:567-1318`) maps RR
     frequencies into `tabConvFreqList` + knobs: FM -> 25 kHz else 12.5 kHz;
     `PL x` -> CTCSS x*10; `DPL ooo` -> DCS octal; `NAC hhh` -> hex NAC;
     `CC n` -> color code; zones filled 8 knobs at a time in mode 33.
   - Talkgroup CSV (RadioReference export) import needs columns `Decimal` and
     `Alpha Tag` (`View/View.P25TSystem/P25TGroupListControl.cs:691`), TGID
     1..65535 (`ImportCsvForTGIDControl.cs:117`).
4. **From the library**: "Add from resources" (`button_addBySelect_Click`,

## 6. Schema versioning

There are two independent version axes. Don't confuse them.

### 6.1 PC profile DB version (`tabDBVersion` MainVersion/SubVersion)

The template `PPS_G4A.db` is **8.0** (`tabDBVersion` row `8|0|New PPS Version`).
(`tabPPSVersion` = `2|31|PPS Version Test` is a separate, unused-looking marker.)

Upgrade path, `View/View.UpdateVersion/DBUpdateChecker.cs:155-235`:

1. Read `tabDBVersion` of the template and the user profile, format as `"<Main>P<Sub>"`
   (`"0P10"` is normalised to `"1P0"`).
2. Walk the ordered list `0P1 .. 6P4, 6P4A, 6P4B, 6P5 .. 6P9, 8P0`
   (`DBUpdateChecker.cs:21-31`) applying `DBUpdateFactory.Create(from, to)`
   (`DBUpdateFactory.cs:5-82`). If no step handler exists, it jumps straight to
   the target; **any** jump whose target is `8P0` uses
   `UpdateVersionXXX_8P0` (`DBUpdateFactory.cs:8-11`). There are no handlers
   below 4P1, so profiles older than 4.1 effectively go directly through
   `XXX_8P0`.
3. Then `CheckDBHolonomic` -> `SQLiteSynchronise.synchronizeDB(profile, template)`
   (`DataBase/Unication.SQLite/SQLiteSynchronise.cs:241-347`): create any table
   that exists in the template but not the profile (copying template rows),
   **drop** any profile table not in the template, rebuild any table whose
   column set differs (copying matching columns), and overwrite `tabDBVersion`.
   So structurally the template is authoritative and old columns vanish.
4. `CheckFunction` (`DBUpdateChecker.cs:46-135`) re-syncs `tabFunctionList`,
   `tabLeaderFunctionList`, `tabMemberFunctionList` with the model's
   `BSS_G4A.db` `tabFunctionList`.
5. A profile whose `tabModel.Model` does not start with `G` is rejected (`:186-189`).

## 7. Implications for the new app

**Formats and I/O**

- We need a SQLite **2.1** reader *and* writer. Options: embed SQLite 2.8.17
  (public domain C, builds with the flags in 1.1; there are Go/Rust FFI paths),
  or write a pure reader for the 2.x btree format and generate output by
  copying the shipped template and replaying SQL through an embedded 2.8 engine.
  Embedding 2.8.17 is the pragmatic choice. The pager's firmware engine is
  2.8.x (PPS ships 2.8.3, UTF-8 build); keep files in that format.
- Internally we can work in SQLite 3 (`scratch/dump_sqlite2.sh` shows the
  round trip) as long as the output written to the pager is SQLite 2.1 with
  the template's schema. Remember `PRAGMA ignore_check_constraints=ON` on
  import, empty strings in integer columns, UTF-8 text.
- We need to ship (or extract from the user's PPS install) the templates:
  `PPS_G4A.db`, `P25TSystem.db`, `Data_G4A.db`, the per-model `MFG_G4A.db` /
  `BSS_G4A.db`, and `DB_Base_G4A.DBV2.0x.db`. Redistribution rights are an open
  question; reading them from an existing PPS install is the safe default.
- G.729 encoder for custom tones/prompts (8 kHz 16-bit mono in, 10-byte
  frames out, header-included quirk), MD5 sidecar files, Ionic-compatible
  zip for `u3db_PC.zip`.

**What to generate when programming**

- Minimum viable write: `u3db.db` (+ `.md5`) generated for the pager's
  reported U3DB version (start with DBV2.06; 2.01-2.05 differ only slightly,
  section 6.2), plus `u3db_PC.db` and `u3db_PC.zip` (+ `.md5`) in PPS's
  8.0 format so that Unication PPS can still read the pager back. Skipping
  the PC copies would leave the pager unreadable by PPS.
- The converter logic in section 2.4 is the spec for `u3db.db`. The fiddly
  parts: `ZoneKnobID = zone * 100 + knob`, contact ID numbering and bit 31
  on DMR/P25 group addresses, `tabP25TrunkingSites` mixing sites
  (`ItemType 0`) and control channels (`ItemType 1`), the full-spectrum scan
  fill rule, and the tone/prompt ID offsets.
- Apply the `ProfileCheckHandler` rules (2.5) and the UI ranges (3, 5.3)
  ourselves; PPS doesn't re-check at convert time and the pager will accept
  garbage.

**What a hobbyist actually edits** (scanner use, receive only)

1. P25 trunking systems: `tabP25TrunkingSystem` (name, WACN, System ID,
   site-trunking flag, optional full-spectrum hunt ranges),
   `tabP25TrunkingSite`, `tabP25TrunkingControlCH`, talkgroups in the system's
   `tabGroup_New` (TGID + alias + priority/alert). Import from RadioReference
   site and talkgroup CSV exports (column names in 5.2) is the high-value
   feature; the SOAP API needs a premium RR account and an app key.
2. Zones (`tabZone_New`, max 64) and the 8 knob positions per zone
   (`tabReceivingMode_NewG4.CurrentMode` + `ChannelName`), with a detail row in
   `tabP25TrunkingSystemKnob` (system + protocol setting + options) and the
   knob's receive talkgroup list in `tabChannelGroup` (max 64, `SeqNo` for
   priority).
3. Conventional channels: `tabConvFreqList` (Rx Hz, bandwidth) referenced from
   `tabSingleConvCHKnob` (protocol: CSQ / P25C with NAC / DMR with color code;
   CTCSS/DCS via `tabRecvSaList`). Scan lists: `tabMultiChannelScan` +
   `tabMultiCHScanList` (max 16). Free scan: `tabAllBandScan*`.
4. A handful of device settings (section 3.7): alert volume/type, duty
   schedule, backlight, date/time format, decimal vs hex IDs, out-of-range
   alert, voice storage time, TG hold.
5. Optional: custom alert tones / channel announcements, home-screen title and
   logo.

Leave at template defaults: encryption/KMF/OTAR, GPS/GSM/GPRS/photo/army/
console/organization tables, legacy G4 tables (3.1), Engineer-only settings,
function lists (copy from the model's BSS).

**Model handling**

- Pick the model folder by the first 14 chars of the pager's model number.
  For hobbyist G5 units, the relevant facts are band pair (700/800 + one of
  VHF / UHF B-D / low band) and protocol code (64/66/67 have P25 trunking;
  36 doesn't; 67 adds DMR). Frequencies must sit in the band's Rx ranges
  from `Data_G4A.tabRFBandRanges` (`RxTx = 0`). For SX that's 763-776 and
  851-870 MHz.

**Gaps and risks**

- We have no sample of a real pager's `u3db.db` / `u3db_PC.zip`; the converter
  analysis is from code only. A read of a real G5 would let us diff our output
  against PPS's.
- The pager-side readback merge is unimplemented in PPS; settings changed on
  the pager (zone/knob edits, `ModifyByDevice`) are lost. We could do better by
  reverse-mapping `u3db.db`, but that's optional.
- The template's 16 knob rows vs the UI's 8 knobs needs a hardware check
  before we allow more than 8.
- The `.unipps` export format and the RadioReference SOAP flow are documented
  above only at the structural level.
